# Regions: separate workspace

Regions (the kraje, the map and the full-window region screen) live in their own files, so they can be
developed on the `Danko2` branch while catastrophes and the rest of the game are developed elsewhere without
merge conflicts. Region work edits only the files below; other work does not edit them.

## Region files

| File | What it holds |
|---|---|
| `data/regions.json` | the 14 kraje: codes, seats, support offsets, reveal order |
| `data/region_profiles.json` | per kraj: traits, demographics, regional coalition |
| `locales/regions.cs.json` | Czech texts: region names (`region.*`), traits (`trait.*`), parties (`party.*`), demographics (`demo.*`), map labels (`map.*`) and the region screen (`region.screen.*`) |
| `src/regions/` | map (`CzMap.tsx`, `Liquid.tsx`, `MapLife.tsx`, `lifeDirector.ts`, `sprites.ts`, `regionsPath.ts`), map pins (`DemandPin.tsx`, `OpportunityPin.tsx`), region screen (`RegionScreen.tsx`, `RegionChart.tsx`, `RegionDemands.tsx`), styles (`regions.css`), entry point (`index.ts`) |
| `src/core/regions.ts` | region trait multipliers (`traitMult`) |
| `tests/regions.test.ts`, `tests/regions-traits.test.ts`, `tests/life.test.ts` | region, trait and living-map tests |

`src/regions/regionsPath.ts` is generated by `npm run build:map` (`scripts/build-map.ts`); do not edit it by hand.

### Seams into the shared code

The rest of the game touches regions only here. Changing a seam means touching a shared file, so keep
those changes small and tell the other side:

- `src/ui/screens/Game.tsx` renders `CzMap` and `RegionScreen` from `@/regions`.
- `src/ui/modals/ElectionNight.tsx` and `src/ui/screens/MainMenu.tsx` draw the map shapes (`LiquidRegion`,
  `REGION_PATHS`) from `@/regions`.
- `src/ui/store.ts` holds the selected region and the map actors; it imports `@/regions/lifeDirector` and
  `@/regions/regionsPath` directly (importing `@/regions` there would be an import cycle).
- `src/core/effects.ts` applies `traitMult`; `src/core/types.ts` (`RegionsData`, region profile types),
  `src/data/schemas.ts` and `src/data/loader.ts` (region schemas and checks); `config.regions` in `src/config.ts`.
- Regional demands: the rules (`src/core/demands.ts`, `data/demands/`) and the pledge tracker
  (`src/ui/demands/`) are shared; only their region-screen part (`RegionDemands.tsx`) is here.
- Texts the shared UI shows about regions stay in `locales/cs.json` (for example `history.*`, `popup.demand*`,
  `tutorial.*`). Region names are read everywhere through `region.<code>` keys, so keep those keys stable.

Open a pull request from `Danko2` into `main` when a version is ready, and merge `main` into `Danko2` now and
then to pick up the other work.

## Check your changes

```bash
npm run dev
```
Open the game and click a kraj on the map to open the region screen.

```bash
npm test
```
Catches missing texts, unknown region codes or traits, and broken map data.
