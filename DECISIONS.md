# Decisions

Format: `- §ref — decision — why`. Every choice the spec did not dictate, plus blockers.

## Decisions
- plan §1 — Toolchain installed at current majors: TypeScript 6, Vite 8, Vitest 5, Zod 4, ESLint 10 (flat config), React 18.3 — plan fixes React 18; for the rest the latest versions installed cleanly.
- plan §0.1 — Czech-diacritics guard is a Vitest test (`tests/no-czech-in-src.test.ts`) rather than an ESLint rule — simpler, and it runs in the gate.
- plan §0.1 — ESLint forbids `Math.random`, `Date.now`, `window`, `document`, `localStorage` inside `src/core/` — enforces core purity mechanically.
- repo — `Gemini_Generated_Image_*.jpg` (a real politician's likeness) and `Mapa.png` (style reference) are left untracked and not used as assets — satire guardrail (no real likenesses); the map look borrows only the palette idea (dark ground, coloured regions, gold borders).
- P1.4 / spec §12.4 — Map built from GISCO NUTS3 2021 at **1:3M** (not 1:20M) and quantised to 0.1 px instead of per-region simplification — 1:20M has only 10–27 vertices per kraj (visibly crude); quantising keeps shared borders gap-free; the file is still small (23.5 KB). `npm run build:map -- --scale 20M` switches back. The download is cached in `.map-cache/` (gitignored).
- §9.2 — Data files are bundled by Vite (`import.meta.glob('data/**/*.json')`) at build time; the loader itself is environment-agnostic (`src/data/loader.ts`), with a Node adapter in `scripts/lib/nodeData.ts` — no runtime network calls; swapping `data/budget.json` needs only a rebuild, no code change.
- §11 — Filler content lives in files whose name starts with `_` (`_filler.json`); `config.includeDevFiller` decides whether such files are loaded.
- §6.2 — `effects.finances` in data is accepted as an alias of `effects.financesExtra` (normalised by the loader) — the card template in the brief lists "Finances" as a resource effect.
- §7.3 — The validator requires each event's `default` response to exist and to cost 0 PC — a timed-out response must always be applicable.
- §5.3 — Card-count check: warning when a leader has < 18 non-filler cards; error when it has < 3 cards in total (filler included, since filler makes runs possible).
- §4.5 — Ending texts are `[TODO]`; titles are `[TODO] Konec: <group>` — design intent exists in the spec, but final text is content.
- §11 — Dummy budget-vote labels are `[DUMMY] Úsporný/Vyrovnaný/Štědrý rozpočet` with numbers following the spec's design intent (tight −3 % all expenditure, balanced −1 %, generous +2 %).
- §12.3 — "Jak hrát" rules summary is written as UI chrome in `cs.json` (it explains mechanics, it is not game content); tutorial bodies stay `[TODO]` as the spec says.
- plan P1.7 — Filler generator: 22 cards per leader (one per leaning, the rest by leader weights), each with 2–3 resource ranges (one primary gain), 1–3 anger ranges (a trade-off), 1–2 budget changes sized to move Finances by 1–5 points, ~30 % ongoing, 1 filler event each (~1/3 respondable; option `c` = do nothing is the default).
- plan §3.4 — Tick order adopted exactly as plan §3.4: (1) scheduled entries for the day in the order budget vote → chaos → pin spawns → pin expiries; the budget vote stops the tick and the same day is re-processed (remaining entries) on the next tick; (2) drift → ongoing → zero penalties → stand-in penalties → anger decay, then durations; (3) Finances; (4) zero-penalty transitions; (5) built ending, then snap election; (6) every 7th absolute day projection + trend; (7) end of quarter.
- §4.1 — `tick()` processes the current day, then advances; day 1 of a quarter is processed after the draft pick, so a chaos window starting on day 1 still fires.
- §10.2 — Replay anchor is the count of effective ticks (`tickCount`) at the moment of each input, not the game day — several inputs can happen on the same day before/after its tick; the count is unambiguous.
- §10.1 — Log `timestamp`: each entry has the in-game `date` plus `wallTime` from a host-injected clock (`0` headless); replay comparison ignores `wallTime`. `runId` is derived from the seed (the UI generates the seed randomly).
- §4.8 — Drift skips the global negative multiplier (difficulty already has a drift multiplier) but matches `<res>.drift` and, with source filter `drift`, `<res>.loss/gain` modifiers.
- §4.8 — Anger decay (memory fades) is a system mechanic and bypasses the pipeline (no negative multiplier, no modifiers).
- §4.8 / §9.3 — A worsening budget change (revenue down / expenditure up) is "bad for Finances": its changePct gets the global negative multiplier and every `finances.negative`/`finances.loss` multiplier; additive modifiers are ignored for percentages. Mandatory growth goes through the same path (so Austerity Freeze halves it).
- §4.8 — A zero raw value is not changed by additive modifiers (a missing effect stays missing).
- §4.5 / §4.4 — Endings and the snap election are also checked right after every dispatch (not only in the tick), so a card that pushes Oligarchs to 100 ends the run immediately.
- §4.4 — "Reaches 0" is tested with a 1e-9 tolerance (values are clamped, so they hit 0 exactly in practice).
- §4.9 — `quartersCompleted` counts fully finished quarters: 16 after a normal term, `q − 1` after a snap election or ending in quarter q.
- §5.2 — New modifier source `ability` (spec's list has no source for abilities); `any` modifiers still apply.
- §8.1 — Starting PC is 0 (`config.pc.start`); Q1 grants +2 like every other quarter. PC income rounds to whole points.
- §3.1 — `Phase` keeps `finished` in the type for future use; the core ends in `ending` or `election` with the result and score already computed, and the UI presents election night / final screen.
- §10.1 — Extra log types beyond the spec table: `quarter_started` (PC gained), `opportunity_spawned`, `mandatory_growth`, `budget_vote_opened`, `ability_recharged` — useful for analytics, cheap.
- plan §2 — Core modules P2–P5 were written together because `simulation.ts` wires all of them; each phase commit adds that phase's tests and fixes.
- §5.3 — Relaxation level 2 is used only once never-picked cards are exhausted; it then takes the card with the oldest last pick (deterministic, no weighting). Levels 1 and 3 keep the weighted leaning draw. A hand stays at the highest level it reached; `pool_relaxed` is logged once per hand with that level.
- §5.3 — If all available leanings have weight 0, leanings are drawn uniformly (avoids a dead draft).
- §5.2 — Abilities can be used while the game runs or during the draft (not during the budget vote / after the run).
- §6.1 — Rerolls: cost = `rerollBaseCost × rerollCostFactor^n` (1, 2, 4, …) in PC (`config.draft.rerollCurrency`, [OPEN]); the counter lives in the per-quarter draft state, so it resets each quarter.
- §7.1 — A chaos event's chance is capped at 1 after the difficulty multiplier; its `quarterOffset` is capped at `config.chaos.maxQuarterOffset` (3).
- §7.3 — Responses are accepted in any non-terminal phase (the countdown only runs while unpaused, but a click on a visible pop-up is honoured); a timed-out response always applies the event's `default`, whatever `responseId` was sent.
- §7.4 — Pin day, region (weighted by seats = w_r) and reward (weighted by `weight`) are all drawn at quarter start from the `opportunities` stream; the reward is revealed on tap. A pin's lifetime is counted in absolute days, so a pin spawned on day 85 can live into the next quarter.
- §4.7 — The budget-vote roll uses its own `budgetVote` stream; the fail branch is applied as a fixed bundle through the same pipeline (so difficulty and modifiers affect it like any other loss).
- §8 — Upgrades can be bought in any non-terminal phase (the tree pauses the clock and is reachable at any time).
- §4.6 — Election-night noise uses `rng.nextOpen()` (never exactly 0 or 1) so `ln(u/(1−u))` is finite; D'Hondt ties go to the region listed first in `data/regions.json`.
- §4.9 — For an ending, `P_final` is the projection recomputed at the moment of the ending (not the weekly displayed value); same for elections (S, T, P are fresh at election time).
- §13 — Greedy bot value = re-election probability P after the midpoints of the previewed ranges, minus small safety terms when Coalition/Support/Finances/Prestige approach 0 or anger approaches 100 (Oligarchs weighted most) — pure P ignores Finances and Coalition, which made the bot walk into snap elections and endings. Ongoing effects count at half their total. Austerity Freeze is timed to cover the budget vote's mandatory growth; Campaign Mode is used when it raises the value by > 0.03 (or late in the year if it helps at all).
- §13 — The random bot also rerolls (15 % per draft), buys a random affordable upgrade (1 % per day) and uses its ability (0.5 % per day) so replay tests exercise every input kind.
- plan §0.1.7 — UI phases P6–P8 were built in one pass and committed together: every screen shares the store and `Game.tsx` mounts all modals, so P6 alone would not build without stubs. The gate ran on the combined result, followed by browser screenshot checks at 1366×768 and 390×844.
- visual direction — Night-violet ground (#1b1729), gold region borders (#d9b45a, from the `Mapa.png` mood), policy cards as paper memos (#efe6cf) with a stamp-red (#c8352e) "Prosadit" stamp animation as the one signature motion; hard pixel offset shadows, segmented resource bars. Fonts are bundled via npm (`@fontsource/*`), never fetched at runtime: Pixelify Sans (headings), Silkscreen (numerals; Pixelify's 5 reads as S), Atkinson Hyperlegible (body).
- §5.3 art — Placeholder leader sprites are original 16×18 pixel caricatures drawn in code (`LeaderSprite.tsx`), coloured by party, with initials and a 2-frame idle bob; no likeness of real people.
- §4.6 map display — Regions show support as a liquid level instead of a colour tint (requested change): each kraj is a mustard-beige glass (#d6bc6c) clipped to its shape, filled with wine-red liquid (#6b1430, crest #a8334f, back wave #8a2241, spray #c25a72) up to s_r % of the region's bounding-box height; outlines are dark brown so they read on beige. The surface is a two-layer pixel wave (6-unit pixels) with an irregular but seamless profile (mixed integer harmonics over 48/40 columns plus occasional spray pixels); each region has its own offset, speed and phase. Waves scroll one pixel column per step; the level steps to new values when the weekly projection updates; election night fills each region to s_r_final as it is revealed. The liquid no longer uses the party colour. Reduced motion stops waves and level animation. (`src/ui/map/Liquid.tsx`.)
- §4.3 trend arrows — Compare the two latest weekly trend snapshots (7 days apart), so arrows update weekly together with the projection.
- §7.2 — The news pop-up auto-dismiss timer runs in real time (also while paused); the response countdown runs only while the game is running and unpaused. Tapping a news pop-up dismisses it.
- §4.3 — The ≥90 anger warning is presentation logic in the UI store (once per crossing, re-armed below 80); it is not a core log entry.
- §12.3 tutorial — Coach-mark order: draft (shown on the Q1 draft), top bar, map + projection, side panel, first opportunity pin (waits for a pin), upgrade tree. The target is highlighted with a pulsing outline; the clock is paused while a mark is open.
- §6.3 — Cards always list all 4 resources (unaffected ones shown as a muted 0); anger shown as ▲/▼ ranges; ongoing effects with ↻ icon, per-day value and duration.
- §12.2 — Mobile: drawer opened by a "Panel" button; draft and budget-vote options in a scroll-snap carousel with a peek of the next card; pop-ups full width at the bottom.
- dev — `?debug=1` shows the developer overlay (chapter codes, revPct/expPct, balance, finance terms, seed, phase, S/T/P) and exposes the store as `window.__budgetInc` for browser checks; the overlay ignores pointer events.
- plan P10 mobile — Checked in headless Chrome mobile emulation at 375×667 and 390×844 (menu, leader select, draft + tutorial, scrolled carousel, running game, drawer, upgrade tree, pause menu): no horizontal scroll, no visible touch target under 44 px, drawer fully on screen, carousel scrollable. Fixes made: the projection label is shortened to "Projekce" on phones, range chips stack full width with no mid-number wrapping, and the draft coach mark no longer stretches full height.
- plan P10 performance — Measured in headless Chrome (390×844, mobile emulation, CDP CPU throttling ×4, game at 4×): ~142 fps average, p95 frame 7 ms over 8 s. Headless rAF timing is only indicative; not yet measured on a physical mid-range phone. Rendering is slice-subscribed (`useStore(selector)` with shallow equality); ticks are batched into one notification per frame; the map re-tints only when the weekly projection changes.
- plan P10 — Browser checks used `playwright-core` driving the locally installed Chrome from the session scratchpad (not a project dependency).
- §3 / §4.6 regional politics (requested addition; the spec had listed "regional specifics" as later) — Each kraj has a support shift: s_r = clamp(support + offset_r[leader] + shift_r, 0, 100). Shifts come from a seeded start jitter and from a new `regions` block in effect bundles (usable by any card, event, response or opportunity). Regional changes go through the same pipeline as support changes: a regional loss gets the difficulty negative multiplier and `support.loss` modifiers, with source `compromise` for compromise cards. Shifts are capped at ±`config.regions.maxShift` (40) and do not decay.
- §4.6 start jitter — Each run starts with per-kraj jitter, uniform ±`config.regions.startJitter` (6) from a new `regions` RNG stream, then re-centred so the seat-weighted mean is exactly 0. The national average and the starting projection are unchanged; only the distribution varies. Runs remain deterministic and replayable. `startJitter: 0` restores identical regions.
- §6 regional compromises (revised on request: they stand only against each other) — New card type in `data/compromises/*.json`: same effect format as policies, no leaning, at least one `regions` entry. Compromises are never mixed into policy hands; the policy draft is unchanged (3 policies). Instead, a separate **compromise decision** opens mid-quarter in a quarter where a roll succeeds (`config.compromise.chance` 0.75, rolled at quarter start from the `regions` stream). It opens on `config.compromise.day` (45; the budget vote is on day 75), pauses the clock (phase `compromise`, which stops the tick like the budget vote) and offers `choices` (2) distinct compromise cards against each other. The player must make one ("Učinit kompromis"; no skip). Draw order: never-made compromises first (uniform), then those made ≥ `cooldownQuarters` (6) ago, oldest first; the decision is skipped (and logged) if fewer than 2 are available. New input `makeCompromise`; log types `compromise_offered` and `compromise_made` (with the rejected alternative); compromises count as key decisions, with impact adding regional shifts weighted by seat share. Bots: random picks either, greedy picks the higher expected value.
- §11 content — 4 `[DUMMY]` compromises cover the requested variants: region vs. region; regional loss for the Oligarchs' favour; regional gain for Finances (budget expenditure); regional gain at the cost of Oligarch anger. The generator adds 16 `[FILLER]` compromises for both leaders (50 % region vs. region, 25 % regions ↔ oligarchs either way, 25 % regions for Finances). They are generated after the existing filler, so the existing filler cards are byte-identical.
- §4.6 display — The map level still refreshes weekly with the projection (spec). Immediate feedback comes from floating numbers over the affected regions. Cards show per-kraj chips using short region names (`region.short.*`).
- §12.4 living map (requested addition; presentation only) — Small pixel actors on the map read the game state; nothing feeds back into the simulation. Trucks drive between kraje (more when Finances are high, empty below 20; a passed budget vote sends a gold convoy out of Prague). Protest crowds appear where regional support is below `life.crowdBelow`, for groups with anger ≥ `anger.pulseAt` (placards in the group colour), on chaos events and on a failed budget vote. Blackouts come on chaos events and while Finances are low. Fireworks or rain clouds appear over kraje whose regional support moved. An oligarch limo drives to Prague when oligarch anger drops. Cows (1–2) occasionally wander into a rural kraj, graze for about 8 s and leave; they are ordinary actors under the same cap and gap (revised on request: earlier a permanent herd of 10 was not counted). Spawns come from a UI-side RNG seeded `<seed>|life` (never a simulation stream), so replays are unaffected. Every rate and threshold is in `config.life`. Revised on request (too busy): at most 3 actors at once, cows included. The next ambient actor waits until every actor already spawned has finished, plus a random 3–8 s quiet gap (`life.ambientGapMs`); event actors ignore the gap but not the cap. Measured over 60 s at 1×: empty about half the time, quiet stretches up to about 11 s, never more than 3. Sprites are enlarged ×1.6 on phones. They are SVG sprites from string grids with CSS `steps()` motion and ignore pointer events, so region taps still work. Reduced motion spawns nothing and freezes the cows.
- §10.4 charts (requested addition) — The side panel gets a first tab, "Vývoj": a weekly step-line chart of the 4 resources, or of the 5 groups' anger, on one 0–100 axis. It has a legend with current values, a hover/touch crosshair and a screen-reader table. A projection ticker in the map corner shows the last `charts.tickerWeeks` (26) weeks of P with the 50 % line; on phones it sits under the map. `TrendPoint` gains `P` (the weekly projection), pushed with the existing weekly trend point, so it is deterministic. Series colours are the dataviz skill's validated dark categorical slots, in fixed order; they pass all checks on the panel surface.
- §12.1 UI flashes (requested addition) — Resource bars flash green or red on each applied change of ≥ `life.flashMinDelta`. Anger meters shake on a jump. The projection number pops when it changes. A glint sweeps over the upgrade button while something is affordable and over the ability button while it is ready. New pins ping. A "Q{n} · rok {y}" banner sweeps across the map at each new quarter. All use `steps()` and are off with reduced motion.

- §4.7 budget sliders (phase 11, `assignment-budget-sliders-and-minigames.md` Part A) — The vote is a slider per **budget category** (`data/budget_items.json`: Důchody, Neziskovky, Obrana, Školství, Doprava, Zdravotnictví, Zemědělství, Životní prostředí, Státní správa). Each category maps to hidden chapters with weights; one step adds `stepPct × weight` (5 %) to each mapped chapter's `changePct`. Steps −3…+3. Anger, support and pass chance change linearly per step, so previews are exact (min = max). Category names are shown; chapter names and codes are not (Daniel's decision; rule 7 in `CLAUDE.md` reworded).
- §4.7 presets — `data/annual/budget_vote.json` options are presets: a named slider setting (`sliders`) plus `passChanceMod` and an optional base bundle. A preset id is valid only while the sliders match it exactly; moving a slider makes the vote "Vlastní rozpočet" (no preset modifier). The `[DUMMY]` presets now carry their budget effect through sliders instead of `"*"` changes and base effects, so the old "Tight = −3 % on every chapter" is gone (Tight ≈ −2.7 % of total spending). Log `budget_vote` stores `presetId`, `sliders`, `redLines`, `violations` instead of `optionId`.
- §4.7 red lines — At vote open, 1–2 categories with `canBeRedLine` are drawn from the `budgetVote` stream (`config.budgetVote.redLines`). Cutting one by more than `maxCutSteps` (1 = 5 %) is allowed but costs `passPenalty` (0.20) of pass chance per violation. Drawing them shifts the `budgetVote` stream (pass rolls differ from earlier versions; runs stay deterministic).
- §4.7 bots — random: random preset, then 0–3 random ±1 nudges. greedy: best preset by expected value, then up to 2 passes of a ±1 hill-climb over the sliders.
- §4.7 phone layout — The full preview card sits below the sliders; a sticky bottom bar shows the Finance change, pass chance and the submit button.
- §6 compromise channels (phase 12, `assignment-budget-sliders-and-minigames.md` Part B) — After picking a deal the player picks a channel (Tisková zpráva, TV debata, Objezd regionů) and plays its mini-game. The UI dispatches `makeCompromise { cardId, channelId, score }`; the core rounds the score to 2 decimals and scales the deal: gains × gainMult, losses × lossMult (anger drops count as gains; budget changes that worsen the balance count as losses). Multipliers are piecewise linear through (0, atZero), (`neutralScore` 0.5, 1), (1, atOne), so a score of 0.5 gives exactly the plain deal; all channel numbers are in `config.compromise.channels` (one block for all three channels instead of a separate `tour` block).
- §6 regional tour (Daniel's decision) — Once per game year (`state.tourUsedInYear`), free, not skippable. gainAtZero −0.5, so a bad tour turns regional gains into losses; a great tour gives the biggest upside (1.5 vs debate 1.3, press 1.2). The UI says whether the tour helped or hurt.
- §6 skip — Press release and debate can be skipped; a skip counts as score `skipScore` 0.4 (slightly worse than neutral, so playing is worth it).
- §6 mini-games (UI only) — `src/ui/minigames/`: A word catch (12 s), B needle timing (5 questions), C handshakes (12 s). They use real time and UI randomness; the core only sees the final score, which is logged, so replays stay exact. Timings live in `config.minigames`. Words and questions are `[DUMMY]` locale keys listed in `data/minigames/texts.json` (Daniel writes the real ones). Positions are computed per animation frame in JS (not CSS animations), so they also work with reduced motion.
- §6 bots — random: random available channel, uniform random score. greedy: best (deal, channel) pair by expected value at `config.bots.greedyMinigameScore` 0.75.
- §6 balance — With debate 1.6 / tour 1.8 upsides greedy Mupka reached 41.8 % (above target); lowered to 1.3 / 1.5 → 38.5 %. Win rate is not very sensitive to these (1.4 / 1.6 gave 39.8 %).
- §3 region screen (phase 13, `assignment-regions-and-demands.md` Part B) — Clicking a region opens a full-window screen (replaces the small info box) and pauses the game (`selectedRegion` is part of `effectivePaused`; a player pause stays). Esc, the close button or the browser/device back closes it; arrows switch region. Desktop: two columns; phone: tabs Přehled / Historie / Data.
- §3 region traits — `data/region_profiles.json` gives every kraj one settlement trait, one economy trait and at most one special trait (validated). The trait assignment is a developer DRAFT (`traitsSource`), shown as "Návrh – čeká na potvrzení" until Daniel confirms it. Traits react to optional hidden card `tags` through `config.regions.traitResponse`: the product of factors scales a card's `regions` effects and adds `support × (mult − 1)` to each region's shift (national support unchanged). Previews include these regional changes. Four `[DUMMY]` cards got tags (social, environment, industry, transport) to exercise this.
- §3 demographics and coalitions — Real values are not invented: every statistic ships as `value: null, status: "TODO"` with its official source (ČSÚ, ISPV, MPSV, EU-SILC) and is shown as "—"; regional coalitions ship empty with source and "Doplníme z oficiálních zdrojů". Praha is marked `council: "city"` (city council, not a kraj council). Party labels (`data/parties.json`) are abbreviations only; no people's names.
- §3 regional history — `state.regionHistory` stores s_r of every region and national support once per projection week (plus the start), and is part of the JSON export. The effects list is built from the log (`deltas.regions`), not a second store; it shows region-specific changes only (national changes move every region equally). Chart: one gold data series, national support as a muted dashed reference line, marker shape = source type (circle policy, square compromise, diamond request, triangle event), crosshair tooltip, table view.
- §7 regional demands (phase 14, `assignment-regions-and-demands.md` Part C) — New scheduled kinds `demandSpawn` / `demandExpire` and a new RNG stream `demands` (other streams unchanged). At each year-start quarter, `perYear` (3) spawn days are drawn inside the year. A spawn picks a template in random order, a free region (no open demand or pledge there) weighted by seats × `regionWeights` per trait, and a requester: a party from the region's coalition (falls back to the template's `parties` while the regional coalitions are TODO) or an interest group. A template only spawns if at least one condition is feasible before the deadline (a matching card or compromise exists for the leader; a budget vote falls inside the window). Max 2 open pins.
- §7 demand outcomes — Accept → `onAccept` + pledge with a deadline of `deadlineQuarters` (4); reject → `onReject`; ignored pin (30 days) → `onReject × ignoreFactor` (0.5). A pledge is fulfilled by any one condition: a policy pick with a matching tag or id, a compromise whose applied regional delta in the region reaches `minRegionGain`, or a **passed** budget vote with the slider at least `minSteps` (or at most, for cuts). Past the deadline it fails once (`onFail`). All through the pipeline with new source `demand`. New inputs `acceptDemand` / `rejectDemand`; log `demand_spawned/accepted/rejected/ignored/skipped`, `pledge_fulfilled/failed` (the last two are key decisions). Active pledges boost matching cards and compromises in the draft (×`draftBoost` 2) and show badges on cards and sliders.
- §7 demand UI — The PC bubble now shows "PK" on a gold coin; "!" is only the demand pin (red speech bubble with a life bar). Tapping "!" opens the region screen with the demand card on top (who, what, deadline, how to fulfil, and honest ranges for accept / fulfil / fail / reject). A pledge tracker sits on the map (top left) and regions with a pledge get an hourglass marker.
- §7 demand content — 7 `[DUMMY]` demands (party and interest-group requesters; policy, compromise and budget conditions), one of them Daniel's Karlovarský parking example. Party demands from real programmes: `sources/programmes/` (README explains the layout); non-DUMMY party demands require `programmeRef` (load error otherwise), `DRAFT` demands only load with `includeDevFiller`. No programmes are uploaded yet.
- §7 demand balance — Coalition penalties in demands were moved to regional penalties: coalition losses trigger snap elections, which are easy wins at high support, so harsher coalition penalties *raised* greedy win rates. Accepting is only a token gesture (±1); fulfilling pays modestly.

- §8 skill tree workspace — Skill trees are separated from the main code so Daniel can design them in parallel (`SKILLTREE.md`): tree texts moved from `locales/cs.json` to `locales/skilltree.cs.json` (merged at load in `src/i18n/locale.ts`; a key may live in only one file, tested). Trees may be leader-specific (`"leader"` in `data/upgrades/*.json`); `treesFor(sim)` filters them for the engine, bots and UI, and the tree screen shows tabs when a leader has more than one tree. A starter `data/upgrades/abis.json` uses only existing modifier targets with `[DUMMY]` texts; it raises greedy Abis from ~58 % to ~72 % on Normal, to be balanced by Daniel's design.
- §8.3 — skill-tree UI moved to `src/skilltree/` (modal, HUD button, own CSS) and its UI chrome to `locales/skilltree.cs.json`; the HUD button glints only for the leader's own trees — skill tree is developed on its own branch, so it must not share files with the rest
- §8 political compass — From the team's sketch: one shared tree, `data/upgrades/compass.json` (28 boxes on a 9×9 grid, Levice/Pravice × Progrese/Tradice), replaces the Public Support tree and the starter Abis tree. New rules in `core/upgrades.ts`: each leader owns a `start` box for free (effects active from day 1, no `upgrade_bought` log); `links` are undirected paths (a box opens when a linked box is owned); `exclusive` groups are forks (owning one marks the others `excluded`). Forks are the Y-splits on both sides (8 pairs). Buying a fork box needs a confirmation, and fork links show a lock. All texts and effects are `[DUMMY]`; start boxes are placeholders: Mupka `c_r1t`, Abis `c_l1t` (mirror positions). The old support tree is now a test fixture, so the modifier pipeline tests stay. Difficulty direction (1000 runs/row): greedy Mupka easy 89.4 % → normal 29.7 % → hard 5.0 %; greedy Abis 100 % → 91.3 % → 59.2 %; random Mupka 10.7 % → 1.0 % → 0.1 %; random Abis 93.3 % → 43.8 % → 13.0 %. All move in the expected direction.

**After adding regional compromises** as a separate two-card decision (1000 runs/row, Normal): random Mupka 0.6 %, random Abis 41.0 %, greedy Mupka 35.9 %, greedy Abis 85.7 %. Greedy Mupka is still within target; compromises add an extra decision, so good play gains a little. Regional spread (std dev of shifts) goes from 3.3 at the start to about 6.9 at the end, and the gap between the strongest and weakest kraj from about 10 to about 24 points. Bots make 10–12 compromises per run.

**Targets met:** random Mupka ≤ 15 %, greedy Mupka 20–40 %, greedy Mupka run length ≈ 16 quarters (15.4).
**Targets NOT met:** random Abis (43 % > 15 %), greedy Abis (90 % > 40 %), leader parity (61 pp gap > 10 pp).
- Cause (structural, in leader data, not config): Bander Abis starts with support 55 vs 40 and Campaign Mode adds +10 support every year (~+40 over a term), while Mupka's Austerity Freeze only protects Finances, which the election formula (§4.6) does not use. Config knobs act on both leaders equally, so they cannot close the gap.
- Measured proposal for Daniel (in-memory experiment, not applied; spec §5.1 values are kept): Campaign Mode support +10 → +5 **and** Abis start support 55 → 45 gives greedy Abis 43 % / random Abis 7 % (vs greedy Mupka 24 % at T_base 47). Closing the rest probably needs Austerity Freeze to touch P (or Mupka to get a support-side ability).
- The Oligarchs ending never fired in bot runs (greedy avoids it; random picks spread anger over 5 groups and anger decays ~1.8/quarter). It is reachable through deliberate play (e.g. the `[DUMMY] Karta 6` +15…20). Real content with stronger oligarch trade-offs will make it rarer-but-possible as intended.
